# SDK Roadmap — internal dev tracking

**Private.** This is the detailed engineering backlog for the Kuira Android SDK —
the source the public `kuira-sdk-android/docs/roadmap.md` is distilled from. It
keeps the full context the public page strips: internal task IDs, dated status
notes, the exact example-app workarounds, source paths, and links into this
(private) monorepo. Do not copy rows verbatim into the public docs — promote
only the forward-looking capability, with no IDs/dates/paths/private links.

Items are added as real dApps (BBoard, Midnight Kicks, the Kuira Starter,
CipherDefense) hit the same friction. Most wait until a second consumer hits the
same gap. Each row records the example-app workaround in use today.

| 35 | 🟡 Cross-app dust/state sync — DEFERRED to Sigil v2 (identity-model gated) | Sharing one wallet's dust across sibling apps is an identity-model decision: apps share dust only if they share `rpId` → same passkey → same seed. | 36 | 🟡 Dust cloud-sync optimization — fresher save-away + tip-aware delta + replay progress | (a) `backupDustToCloud` only fires inside throttled `refresh()` + manual tap → Drive checkpoint lags local → staler restores → larger delta. (c) native replay emits no progress → small deltas look frozen; emit a heartbeat. | Upload piggybacks throttled `refresh()`; delta not tip-aware; native replay reports no progress. |
| 37 | 🟡 True dust-backup disable — Drive consent revoke + appData blob delete | "Disable" today is an **opt-out gate only**: `MidnightWallet.dustBackupEnabled = false` (persisted `dust_backup_opted_out`) just stops further uploads — the Google `drive.appdata` grant and the already-stored checkpoint blob both remain. A real off should (a) `DriveAuthManager.revoke()` the OAuth grant and (b) `DustCloudBackup.delete(walletAddress)` the stored blob, so nothing of the user's lingers in Drive after they turn it off. `DriveAuthManager` currently exposes only `authorize()` / `tokenFromConsent()` — no revoke; GMS revoke is fiddly. | Opt-out flag stops new uploads; existing grant + Drive blob persist. |

## Related (separately tracked)

- **Checkpoint consistency / `NonLinearInsertion`** — atomic `saveCheckpoint`/`loadCheckpoint` so a torn (state, cursor) pair can't be persisted or restored; self-heal after one genesis sync. Fixed in alpha02.
- **Proactive background dust-sync** — keep the dust state current ahead of need so a tx never waits on a cold sync (delta-only, energy-efficient). alpha03 target.
